# 每日一字应用体验优化方案

## 1. 问题分析

### 1.1 列表页数据加载问题

* **现象**：进入列表页后提示“加载中”，然后显示“暂无符合条件的汉字”，最后才显示出符合条件的数据

* **原因**：数据加载流程存在时序问题

  * `loadCharacters`方法获取数据后，先设置`loading: false`，再调用`updateCharacterList`更新列表

  * `updateCharacterList`方法需要时间处理数据并更新UI

  * 导致UI在数据准备好之前就显示了空状态

### 1.2 首页字卡刷新问题

* **现象**：从列表页返回首页时，字卡会刷新，显示新的随机汉字

* **原因**：`index.js`的`onShow`方法每次都会重新过滤汉字并加载随机字

  * `onShow`调用`filterCharacters`

  * `filterCharacters`调用`loadRandomCharacter`

  * 导致每次返回首页都会显示新的随机汉字

## 2. 解决方案

### 2.1 列表页数据加载优化

* **修改文件**：`/Users/joshua/Documents/GitHub/Chinesetraditional-miniprogram/subgames/daily-character/pages/list/list.js`

* **修改思路**：确保在数据完全准备好之前，保持`loading: true`状态

* **具体修改**：

  1. 将`updateCharacterList`方法改为同步更新所有数据
  2. 在`loadCharacters`方法中，仅在所有数据处理完成后才设置`loading: false`
  3. 确保`paginationData`在`loading: false`之前已更新

### 2.2 首页字卡状态保持

* **修改文件**：`/Users/joshua/Documents/GitHub/Chinesetraditional-miniprogram/subgames/daily-character/index.js`

* **修改思路**：仅在必要时才刷新字卡，从列表页返回时保持原有字卡不变

* **具体修改**：

  1. 修改`onShow`方法，移除自动刷新字卡的逻辑
  2. 仅在首次加载或难度设置变更时刷新字卡
  3. 添加状态标识，记录字卡是否已经初始化

## 3. 实施步骤

### 3.1 优化列表页数据加载

1. **修改`loadCharacters`方法**：

   * 移除`setData({ loading: false })`的提前调用

   * 确保在所有数据处理完成后才更新`loading`状态

2. **修改`updateCharacterList`方法**：

   * 确保数据处理的原子性

   * 避免中间状态的UI闪烁

### 3.2 保持首页字卡状态

1. **修改`onShow`方法**：

   * 移除自动调用`filterCharacters`的逻辑

   * 添加条件判断，仅在首次加载时初始化字卡

2. **修改`filterCharacters`方法**：

   * 移除自动调用`loadRandomCharacter`的逻辑

   * 仅在难度设置变更时才更新当前显示的字卡

3. **添加状态标识**：

   * 在`data`中添加`isInitialized`状态，记录字卡是否已经初始化

   * 确保从列表页返回时，不会重新初始化字卡

## 4. 预期效果

* **列表页**：进入列表页后显示“加载中”，数据准备好后直接显示符合条件的数据，不再显示“暂无符合条件的汉字”

* **首页**：从列表页返回时，保持原有字卡不变，提供更流畅的用户体验

* **整体**：应用体验更加流畅，避免不必要的UI闪烁和数据刷新

## 5. 风险评估

* **低风险**：修改内容集中在UI逻辑和生命周期方法，不影响核心功能

* **低风险**：保持了原有的数据加载和处理逻辑，仅调整了时序和条件

* **无风险**：修改后的代码更符合用户预期，提高了应用的易用性
