# 每日一字应用设置页面优化方案

## 1. 问题分析

* **现象**：首次进入设置页面时，显示的是默认设置状态（全部难度级别都选中，测试难度为"均衡"），而后设置后，再次进入就会读取上次设置状态，显示正常

* **原因**：

  * 页面数据初始化时，`tempDifficulties` 被硬编码为默认值（全部为 true）
  * `onLoad` 方法只将本地存储的设置更新到 `difficultyBeginner` 等变量，没有同步更新 `tempDifficulties`
  * `tempDifficulties` 只有在 `openSettings` 方法执行时才会被更新为正确值
  * 测试难度虽然在 `onLoad` 中被正确初始化，但为了保持一致性，也需要确保其处理逻辑正确

## 2. 解决方案

* **修改文件**：`/Users/joshua/Documents/GitHub/Chinesetraditional-miniprogram/subgames/daily-character/index.js`

* **修改思路**：确保所有设置状态在页面初始化时就从本地存储中读取正确的值，当没有读取到设置时，使用默认值初始化，且始终保持同步

* **具体修改**：

  1. 在 `onLoad` 方法中，将读取到的难度设置同时更新到 `tempDifficulties` 中
  2. 当没有本地存储时，使用默认值初始化 `tempDifficulties`
  3. 确保 `tempDifficulties` 始终与 `difficultyBeginner` 等变量保持一致
  4. 检查测试难度的初始化逻辑，确保其正确处理本地存储和默认值

## 3. 实施步骤

### 3.1 修改 `onLoad` 方法

* 在 `onLoad` 方法中，当读取到本地存储的设置后，同时更新 `tempDifficulties`
* 当没有本地存储时，使用默认值初始化 `tempDifficulties`
* 确保 `tempDifficulties` 与 `difficultyBeginner` 等变量保持一致
* 确认测试难度的初始化逻辑正确

### 3.2 优化 `openSettings` 方法

* 保留 `openSettings` 方法中的同步逻辑，作为双重保障
* 确保每次打开设置页面时，`tempDifficulties` 都能与当前设置保持一致

## 4. 预期效果

* 首次进入设置页面时，直接显示正确的设置状态（本地存储值或默认值）
* 避免设置页面打开时的视觉闪烁
* 确保所有设置状态（包括难度选择和测试难度）始终保持同步
* 提高用户体验，让用户感受到设置状态的连续性

## 5. 风险评估

* **低风险**：修改内容集中在初始化逻辑，不影响核心功能
* **低风险**：保持了原有的数据结构和处理逻辑，仅调整了初始化时机
* **无风险**：修改后的代码更符合用户预期，提高了应用的易用性

## 6. 实施代码

### 6.1 修改 `onLoad` 方法

```javascript
// 在onLoad方法中，设置初始状态时，同时更新tempDifficulties
this.setData({
  difficultyBeginner,
  difficultyIntermediate,
  difficultyAdvanced,
  difficultyChallenge,
  // 初始化临时难度为当前难度，确保首次打开设置页面时显示正确状态
  tempDifficulties: {
    beginner: difficultyBeginner,
    intermediate: difficultyIntermediate,
    advanced: difficultyAdvanced,
    challenge: difficultyChallenge
  },
  testDifficulty
});
```

### 6.2 保留 `openSettings` 方法

```javascript
openSettings() {
  // 打开设置窗口前，将当前难度设置同步到临时变量（作为双重保障）
  this.setData({
    settingVisible: true,
    tempDifficulties: {
      beginner: this.data.difficultyBeginner,
      intermediate: this.data.difficultyIntermediate,
      advanced: this.data.difficultyAdvanced,
      challenge: this.data.difficultyChallenge
    }
  });
}
```

## 7. 测试难度设置检查

* 测试难度的初始化逻辑已经正确，在 `onLoad` 方法中：
  ```javascript
  // 读取测试难度设置
  const savedTestDifficulty = wx.getStorageSync('dailyCharacterTestDifficulty');
  const testDifficulty = savedTestDifficulty || '均衡';
  ```
* 测试难度不需要临时变量，直接绑定到页面数据，因此不会出现类似的问题
* 当没有本地存储时，会使用默认值 '均衡'
* 保存设置时，会将测试难度保存到本地存储：
  ```javascript
  // 保存测试难度到本地存储
  wx.setStorageSync('dailyCharacterTestDifficulty', testDifficulty);
  ```

这个方案将确保：

1. 首次进入设置页面时，难度选择显示正确（从本地存储读取或使用默认值）
2. 测试难度的初始化逻辑正确，始终显示正确状态
3. 避免设置页面打开时的视觉闪烁
4. 确保所有设置状态始终保持一致

通过这个方案，可以有效解决设置页面首次进入时显示默认状态的问题，提高用户体验。
