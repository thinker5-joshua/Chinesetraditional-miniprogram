# 每日一字测试难度设置实施计划

## 一、改造目标
实现每日一字测试功能根据用户设置的难度和测试难度来配置测试题目的方案，提高测试的针对性和有效性。

## 二、改造内容

### 1. 修改测试页面数据初始化
- **文件**: `/subgames/daily-character/pages/test/index.js`
- **内容**: 在data中添加用户设置的难度和测试难度字段，确保它们被正确初始化
- **预期效果**: 确保测试页面能够正确存储和使用用户设置的难度信息

### 2. 添加读取用户设置功能
- **文件**: `/subgames/daily-character/pages/test/index.js`
- **内容**: 添加`readUserSettings`方法，读取用户设置的难度和测试难度
- **预期效果**: 测试页面能够正确读取用户在设置中选择的难度和测试难度

### 3. 实现难度分配算法
- **文件**: `/subgames/daily-character/pages/test/index.js`
- **内容**: 添加`getDifficultyDistribution`方法，根据测试难度分配不同难度级别的汉字数量
- **预期效果**: 能够根据不同测试难度（容易、均衡、挑战）生成不同的难度分布

### 4. 实现汉字选择功能
- **文件**: `/subgames/daily-character/pages/test/index.js`
- **内容**: 添加`selectCharactersByDifficulty`方法，从指定难度级别的汉字中随机选择指定数量的汉字
- **预期效果**: 能够根据分配数量选择对应难度的汉字，确保测试题目的多样性

### 5. 修改测试题目生成逻辑
- **文件**: `/subgames/daily-character/pages/test/index.js`
- **内容**: 修改`generateTestQuestions`方法，实现以下功能：
  - 根据用户设置的难度开关过滤汉字
  - 根据测试难度分配不同难度级别的汉字数量
  - 根据分配数量选择对应难度的汉字
  - 为每个选中的汉字生成测试题
  - 打乱测试题目顺序
  - 处理无符合条件汉字的情况
- **预期效果**: 能够生成符合用户设置的难度和测试难度的测试题目

## 三、具体实施步骤

### 步骤1: 修改测试页面数据初始化
1. 在测试页面的data中添加userDifficulties和testDifficulty字段
2. 初始化userDifficulties为默认值（全部难度开启）
3. 初始化testDifficulty为默认值（均衡）

### 步骤2: 添加读取用户设置功能
1. 添加readUserSettings方法
2. 从本地存储中读取用户设置的难度和测试难度
3. 将读取到的设置更新到页面数据中

### 步骤3: 实现难度分配算法
1. 添加getDifficultyDistribution方法
2. 根据测试难度设置不同的分配比例
3. 确保分配的数量不超过实际可用数量
4. 实现测试题目不足时的补充逻辑

### 步骤4: 实现汉字选择功能
1. 添加selectCharactersByDifficulty方法
2. 从指定难度级别的汉字中随机选择指定数量的汉字
3. 确保选中的汉字不重复

### 步骤5: 修改测试题目生成逻辑
1. 修改generateTestQuestions方法，调用readUserSettings读取用户设置
2. 根据用户设置的难度开关过滤汉字
3. 调用getDifficultyDistribution获取难度分配
4. 调用selectCharactersByDifficulty选择汉字
5. 生成测试题目并打乱顺序
6. 处理无符合条件汉字的情况

## 四、预期效果

1. **用户设置的难度开关生效**：测试题目只会从用户开启的难度级别中选择
2. **测试难度设置生效**：根据用户选择的测试难度，生成不同难度分布的测试题目
3. **测试题目多样性**：确保测试题目来自不同难度级别，增加测试的全面性
4. **测试题目数量稳定**：无论何种情况，总能生成5道测试题，保证测试的完整性
5. **测试题目顺序随机**：增加测试的随机性，避免用户记住题目顺序

## 五、测试要点

1. 测试不同难度开关组合下的测试题目生成
2. 测试不同测试难度下的测试题目分布
3. 测试边界情况（如只有一种难度级别开启）
4. 测试测试题目数量是否稳定为5个
5. 测试测试题目顺序是否随机

## 六、风险评估

1. **数据风险**：如果汉字数据中没有正确设置difficultyLevel字段，可能导致测试题目生成失败
2. **性能风险**：在汉字数量较多时，过滤和选择汉字可能会影响性能
3. **用户体验风险**：如果测试难度分配不合理，可能导致测试过于简单或困难

## 七、应对措施

1. 确保汉字数据中正确设置difficultyLevel字段
2. 优化过滤和选择汉字的算法，提高性能
3. 根据实际使用情况调整难度分布比例，确保测试难度适中

## 八、验收标准

1. 测试页面能够正确读取用户设置的难度和测试难度
2. 测试题目能够根据用户设置的难度开关进行过滤
3. 测试题目能够根据测试难度设置生成不同的难度分布
4. 测试题目数量稳定为5个
5. 测试题目顺序随机
6. 无符合条件汉字时能够正确处理

## 九、后续优化方向

1. 增加更多的测试难度选项
2. 实现根据用户历史测试成绩自动调整测试难度
3. 增加测试题目的类型（如拼音选择、字形选择等）
4. 实现测试题目的个性化推荐

## 十、实施时间

预计实施时间为1-2小时，包括代码修改、测试和调试。
