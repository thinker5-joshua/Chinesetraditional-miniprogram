# 每日一字应用移除本地备用数据机制方案

## 1. 需求分析

用户要求：

* 移除主应用中使用 `data-optimized.js` 作为云数据库加载失败时的本地备用数据机制

* 当云数据库读取失败时，直接提示用户："无法获取云数据库字卡，请重试..."

* 目的：减小小程序大小，避免数据不一致

## 2. 现状分析

当前代码位置：`index.js:185-199`

* 当云数据库加载失败时，会尝试加载本地的 `data-optimized.js` 文件

* 如果本地文件也加载失败，才会显示错误提示

## 3. 处理方案

### 3.1 修改主应用 (`index.js`)

1. **移除本地备用数据加载逻辑**：删除 `catch` 块中第186-197行的代码
2. **简化错误处理**：在云数据库加载失败时，直接显示错误提示
3. **移除对** **`data-optimized.js`** **的依赖**：确保应用不再引用本地数据文件

### 3.2 测试脚本处理

* 保留测试脚本不变，因为它们不影响小程序的大小和运行

* 理由：测试脚本用于开发和调试，不包含在最终发布的小程序中

### 3.3 临时工具脚本 (`temp/` 目录)

* 保留现状，不做修改

* 理由：这些脚本是用于数据处理的临时工具，不影响小程序正常运行

## 4. 实施步骤

### 4.1 修改 `index.js` 文件

1. **定位代码**：找到 `index.js` 中云数据库加载失败的 `catch` 块（第182-199行）
2. **修改代码**：

   * 删除第186-197行的本地备用数据加载逻辑

   * 修改错误处理，直接显示"无法获取云数据库字卡，请重试..."提示
3. **验证修改**：确保代码语法正确，逻辑合理

### 4.2 验证应用功能

1. **测试正常加载流程**：确保云数据库正常时，应用能正常加载数据
2. **测试失败场景**：模拟云数据库加载失败，确保能正确显示错误提示
3. **检查小程序大小**：确认移除本地数据文件引用后，小程序大小有所减少

## 5. 预期效果

* 小程序大小减小，因为不再包含本地数据文件的引用

* 数据一致性提高，因为所有数据都来自云数据库

* 错误提示更加明确，用户体验更好

* 代码结构更简洁，便于维护

## 6. 风险评估

* **低风险**：移除本地备用数据机制后，应用对网络和云数据库的依赖性提高

* **缓解措施**：明确的错误提示可以引导用户重试，提高用户体验

## 7. 实施代码

```javascript
// 修改前
} catch (error) {
  console.error('加载数据失败:', error);
  
  // 加载失败时使用本地备用数据
  try {
    const characters = require('./data-optimized.js').characters;
    this.setData({
      allCharacters: characters,
      filteredCharacters: characters,
      loading: false
    });
    this.loadRandomCharacter();
  } catch (localError) {
    console.error('加载本地备用数据失败:', localError);
    this.setData({ loading: false });
    wx.showToast({
      title: '加载数据失败，请重试',
      icon: 'none'
    });
  }
}

// 修改后
} catch (error) {
  console.error('加载数据失败:', error);
  this.setData({ loading: false });
  wx.showToast({
    title: '无法获取云数据库字卡，请重试...',
    icon: 'none'
  });
}
```

这个方案将确保每日一字应用不再使用本地备用数据，所有数据都来自云数据库，同时保持良好的用户体验。
